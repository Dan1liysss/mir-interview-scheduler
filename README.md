# mir-interview-scheduler

Концепт-прототип онлайн-записи на собеседование при поступлении —
предложение по доработке сайта школы «Мир» (mirschool.ru).

**Живая демонстрация:** https://mir-interview-scheduler.danil-mir.workers.dev

> Это демонстрационный прототип, не подключённый к реальной приёмной
> комиссии школы. Пароль секретаря и все данные — тестовые.

## Идея

Собеседование ведёт лично директор, график у него плотный и меняется
каждый день — заранее нельзя составить список "свободных окон", как
для рядового сотрудника. Заявки при этом обрабатывает секретарь
приёмной комиссии (не сам директор), ориентируясь на его график.
Поэтому вместо календаря со слотами здесь — процесс согласования:

1. Родитель подаёт заявку с желаемой датой/временем.
2. Секретарь в своей панели видит заявку и либо подтверждает именно это
   время, либо предлагает другое (если исходное уже занято).
3. Если время предложено — родитель по личной ссылке подтверждает его,
   отказывается или предлагает своё (до 3 раундов согласования).
4. Итоговый статус виден обеим сторонам в реальном времени.

## Архитектура

- **Cloudflare Workers** — весь backend (JS, без фреймворков и зависимостей).
- **Cloudflare D1** (SQLite на edge) — хранилище заявок и сессий секретаря.
- **Workers Assets** — статика (`public/`) отдаётся тем же Worker'ом.
- Пароль секретаря хранится как Worker Secret (`SECRETARY_PASSWORD`), не в коде.

### Почему не email и не push-уведомления

По ходу обсуждения договорились не подключать реальную отправку почты
(это прототип для питча школе, не продакшн-сервис) — вместо письма
родитель получает персональную ссылку `/status.html?token=...` сразу
после отправки заявки. Уведомления для секретаря реализованы через
`Notification API` браузера + звук + бейдж в заголовке вкладки: это
работает, пока вкладка панели открыта, без серверной push-инфраструктуры
(VAPID-ключи и т.п.) — оправданный компромисс для демо-масштаба.

## Структура

```
wrangler.toml       — конфигурация Worker'а, D1-биндинг, статика
schema.sql           — схема D1 (requests, secretary_sessions)
src/worker.js         — весь backend: роутинг + бизнес-логика
public/
  index.html           — форма заявки (родитель), 3-шаговый визард
  status.html            — личная страница статуса/подтверждения (родитель)
  secretary.html           — панель секретаря (логин, список, действия, уведомления)
  style.css                 — общие стили
  img/school-hero.webp        — фото здания школы (hero на форме заявки)
```

## Локальная разработка

```bash
npm install -g wrangler   # или используйте npx wrangler ...
npx wrangler d1 execute mir-interview-scheduler --local --file=./schema.sql
npx wrangler dev
```

## Деплой

```bash
npx wrangler d1 execute mir-interview-scheduler --remote --file=./schema.sql   # один раз
npx wrangler secret put SECRETARY_PASSWORD                                      # один раз
npx wrangler deploy
```

## API

| Метод | Путь | Кто | Описание |
|---|---|---|---|
| POST | `/api/requests` | родитель | подать заявку, вернёт `status_token` |
| GET | `/api/status/:token` | родитель | статус своей заявки |
| POST | `/api/status/:token/respond` | родитель | `confirm` / `decline` / `counter` |
| POST | `/api/secretary/login` | секретарь | вход по паролю, вернёт `session_token` |
| GET | `/api/secretary/requests` | секретарь | список заявок (`?status=` для фильтра) |
| GET | `/api/secretary/requests/:id` | секретарь | детали заявки (помечает как просмотренную) |
| POST | `/api/secretary/requests/:id/decide` | секретарь | `approve` / `propose` / `reject` |
| GET | `/api/secretary/export.csv` | секретарь | выгрузка всех заявок в CSV |

## Известные ограничения демо-масштаба

- Уведомления секретарю работают только пока вкладка панели открыта в
  браузере (polling раз в 12 сек + Notification API), а не через
  серверный push.
- Нет email/SMS — их функцию временно выполняет персональная ссылка.
- Один общий пароль на секретаря, без multi-user ролей — для реального
  внедрения нужна полноценная авторизация персонала школы.
